# 최초 자동 구축본의 실제 누락과 교정 검증 중단

이 문서는 v1·v2의 당시 실패 기록이다. 같은 두 누락의 후속 선정 개선·보강·재검수 결과는 [후속 실증](initial_build_quantity_repair_20261102.md)에 별도로 기록한다. 아래 실패·미실행 상태는 소급 변경하지 않는다.

**실제 수량 누락 두 건은 확인했지만 자동 검수→교정→재검수 성공은 확인하지 못했다.** 새 질문의 검사 범위를 구성하는 단계에서 의미 오류가 발생했다. 최소 지시 변경도 같은 오류를 남겼으므로 제품 코드는 복원하고 실패 증빙만 보존했다.

## 실제 호출 결과

1. 기존 구성 v1은 수량 두 개·부위·간맞춤 조건·재료를 별도 검사로 나눴지만, 수량 검사 두 개의 대상을 전체 질문으로 잡고 `members_of`로 출력했다. 각각의 값을 묻는 요청을 집합 내부 비교로 취급했다. 첫 1회 뒤 후속 호출을 중단했다.
2. v2는 같은 입력·스키마·설정에 “각 대상의 값을 묻는 요청과 대상 사이의 비교를 구분한다”는 지시만 추가했다. 새 원시 응답의 이유 문장은 `one_subject`를 쓰겠다고 설명했지만 실제 검사 두 개는 다시 `members_of`였다. 의미 개선은 확인되지 않았다. 두 번째 실패 뒤 추가 조정·재시도 없이 종료했다.

두 호출 모두 `ready=true`, `errors=[]`, `semantic_status=not_assessed`로 저장됐다. 제품의 주소·형식 검사는 이 의미 오류를 자동 발견하지 못했다. 세션의 원시 응답 대조에서 실패를 확인했다. 모델의 설명과 실제 출력이 불일치한다는 관찰만 확정하며, 스키마나 디코딩이 원인인지는 미검증이다.

| 단계 | 이번 실행 |
| --- | --- |
| 원문 사실 생성 | 요청·설정·스키마·참조·응답이 정확히 일치한 과거 결과 재사용 |

미실행 검수를 성공이나 실패로 계산하지 않는다. 현재 실험 검수의 `actions=[]` 진단 결과를 기존 교정 함수의 검증된 recover/correct 대상으로 잇는 연결도 남아 있다. 수동 교정 대상이나 가짜 검수 결과를 만들어 우회하지 않았다.
