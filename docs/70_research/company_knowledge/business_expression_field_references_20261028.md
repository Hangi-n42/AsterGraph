# 저장 표현의 전체 필드 참조 연결

## 진행 이유와 변경 범위

R이 이미 전달받은 저장 표현을 `claim_id/field/quote`로 다시 작성하는 부분만 참조 선택과 서버 복원으로 바꿨다. 의미 요약인 `represented_content`, 누락 내용, 이유, represented/partial/missing 판정과 필수·참고 선택은 기존 R의 책임이다. 위치 검증은 의미 지지나 승인 지식의 증거가 아니다.

기준은 PR #674의 `768c9640519abcfbf3dcb957975c120bada8ca64`다. 해당 PR은 확인 시점에 open/unmerged이고 main은 `fab7e1fe87960659b2ba386c827f47078d5c2dac`이다. 현재 main에는 별도의 B1/B2 관측 호출이 없으므로 main에서 모델 호출을 제거한 변경으로 설명하지 않는다. 새 진단 API나 별도 검수 단계를 만들지 않고 기존 `business_run.json_request/json_call → bind_requirement_check → 요약/repair 보류 → save/GET`에 연결했다.

260f1393 전체 브랜치, 이전 별도 비교 모듈, 다른 작업트리의 미커밋 변경은 가져오지 않았다. 선행 패치는 B1의 입력 예산 초과를 해소하기 위해 필요했다. 원본 `PREREQUISITE.patch`와 테스트의 바이트 일치를 확인했다. 이 브랜치는 PR674에 의존하며 기존 PR674를 수정하거나 새 PR을 만들지 않는다.

## 참조 계약

- 비어 있지 않은 `required_content_targets`가 있는 기존 표현 검수·합성 스키마에만 적용한다. 모델에는 이미 전달된 claim의 필드와 `expression_ref` 목록을 제공하며 quote/version/span을 중복 전달하지 않는다.
- raw Head/Relation/Tail/Event, 문자열 Entity·raw.fields, 기존 해석의 의미 값과 조건·예외·기간·참조 문자열만 허용한다. evidence/reason 및 중첩 evidence 메타데이터는 저장 표현으로 세지 않는다. compact 입력에서 사라졌거나 ID 치환으로 값이 달라진 필드는 제외한다.
- 서버가 현재 claim 버전, 유일한 소유자, 필드 값과 전체 span을 대조한 뒤 기존 `claim_id/field/quote`로 복원한다. 같은 값도 소유 claim은 합치지 않는다. 부분 인용을 전체 필드로 임의 확대하지 않는다.
- 미지의 ID, 중복, 잘못된 소유자·버전·값·span, 예전 quote 객체는 해당 행을 unknown/unbound로 남긴다. 다른 정상 행은 유지한다. JSON 최상위나 행 자체의 형식 오류는 기존 전체 스키마 실패 경계를 유지한다.
- `whole_field_not_semantic_support`를 기록한다. raw와 interpretation, 원래 오류·미확정 상태, Entity와 행위 주체의 차이는 그대로 남는다. 교정·보류·승인 규칙은 바꾸지 않았다.

## 입력 예산과 비용

동일 모델 digest와 검증된 로컬 renderer로 계산했다. 표는 입력 토큰에 별도 schema 예산, 출력 8,192, 안전 여유 1,000을 더한 **보수적 예산 추정**이다. 실제 새 모델 실행량이 아니다. 컨텍스트 한도는 49,152다.

| 고정 입력 | PR674 원형 | 필드 참조만 추가 | 적용성 선행 패치만 | 두 변경 결합 | 결합 후 여유 |
|---|---:|---:|---:|---:|---:|
| B1 | 66,719 | 68,866 | 46,300 | 48,447 | 705 |
| B2 | 43,970 | 46,280 | 41,997 | 44,307 | 4,845 |

필드 참조 자체는 선행 패치만 적용한 입력보다 B1 2,147 / B2 2,310 토큰을 추가한다. B2의 결합 예산은 PR674 원형보다 337 높다. 두 입력 모두 비용이 감소했다고 주장하지 않는다. 실제 요청 크기도 선행 패치만 적용했을 때 140,040 / 121,827 bytes에서 결합 후 147,655 / 130,112 bytes로 늘었다. 생성 시간·출력 토큰 절감과 다른 입력의 수용량은 확인하지 않았다.

## 검증 결과와 보존

최종 관련 단위 검사 4개 파일은 **79개 통과, 12.98초**다. 새 참조 검사 17개, 기존 적용성 참조 검사 30개, 필수 하위 내용·교정 입력 참조 검사를 포함한다. 실행한 코드의 해시와 최종 코드가 같다. `git diff --check`도 통과했다.

과거 실제 R unit `5ea940f3e7d149d3af234861c05f19cc`에는 전체 필드와 일치하는 인용 16개가 있고 부분 인용은 0개였다. 선행 패치만 적용한 요청은 그 과거 요청과 messages/schema/reference_map이 정확히 같아 기존 캐시를 **1회** 재사용했다. 결합 요청은 messages/schema가 달라 캐시 일치로 세지 않았다. 그 경우 과거 출력의 인용만 ID로 변환한 저장 응답 어댑터로 실제 `json_call` 소비 경계를 검사했다. 기존 의미 필드, 바인딩과 후속 요약은 전후 같았다. 새 모델의 판단이 같다는 증거는 아니다.

별도의 unknown 합성 응답으로 B1 67개 / B2 75개 필드의 복원, 잘못된 참조 행과 정상 형제의 분리, 실제 동적 합성·재검수 스키마를 확인했다. 합성 unknown 3개는 실제 repair 소비에서 보류됐고 새 교정 unit은 생성되지 않았다. 평범한 합성 스키마에 재검수 전용 enum을 넣은 최초 fixture는 실패했다. 실패 unit `7564d241f18f48c2944800731baedd6b`와 원래 driver를 보존하고 실제 재검수 스키마로 마지막 단계만 수정해 완료했다. 모델 재시도는 아니다.

새 복사 DB의 run `1e6986c17361452ca8888ee60a0971c6`을 저장하고 GET 200과 전체 run 일치를 확인했다. 원본 주장 199개, 교정 changes 2개, assessment 14개, 과거 unit 147개, 기존 33개 run payload와 나머지 17개 테이블은 같았다. 새 unit 7개는 캐시·저장 응답 소비·합성 검사의 기록이며 실패 fixture 1개를 포함한다. 상속 `llm_calls=8`은 이번 새 호출이 아니다. **이번 새 모델 호출 0, 새 교정 dispatch 0**이다.

전체 원문 의미 18개, 대상 의미 10개와 블록 34개를 보존했다. 실제 고정 R 요청은 기존 32개 전달 블록을 유지한다. 원문 literal field 30개와 수량 구문 2필드/13항목의 이전 결과는 같고 미파싱 32블록도 보존했다. 의미 검증이나 실제 표 발견으로 승격하지 않았다. 보호 파일 **1,570개 해시 변화 0**, 기존 서버 **29개 PID/시작 시각/명령 동일**, Ollama 점유 모델 0을 확인했다. 다른 작업트리와 원본 DB는 변경하지 않았다.

## 확인된 한계와 다음 작업

실제 R은 지정 돼지고기 부위가 필요한 레시피에 간 맞추기 claim c10을 선택하고 required 행을 represented로 판정했다. c10의 “찌개가 싱거우면” / “간장이나 소금으로 간을 한다.”라는 인용은 정확히 복원되지만 이 **기존 의미 오판은 그대로 남는다**. 전체 의미 행의 represented+명시 잔여 모순과 이 required 행 오판은 별개다. 정상 B2의 기존 오류도 해결한 것으로 세지 않는다.

로컬 저장 응답 소비에서 실제 R은 2.23초, ID 응답 직렬화는 6,520 bytes, 복원 후 결과는 26,203 bytes였다. 이는 생성 속도나 같은 형식끼리의 압축률이 아니다. GET은 1.59초였고 driver 프로세스 수명 전체 최대 RSS는 6,291,456,000 bytes였다. 대형 보관 데이터·복사 DB·비교가 포함된 측정이며 제품 단독 메모리 또는 native 지연 개선으로 해석하지 않는다.

다음 작업은 PR674 의존성을 유지한 변경 검토다. 새 모델로 의미 정확도·출력 비용을 평가하려면 별도의 실행 범위와 호출 예산이 필요하다. 이번에는 기본 활성화, main 병합, 배포, 지식 승인, 이슈 종료, 신규 QA/검색/PPR/임베딩/추출/의미 판정을 수행하지 않았다. 현재 사용자 결정이 필요한 사항 없음.

검증 원장은 로컬 산출물 `retail_review_expression_field_refs_20261028_v1`에 있다. 주요 파일은 `COMBINED_PREFLIGHT.json`, `ACTUAL_R_BEFORE_AFTER.json`, `SERVICE_SAVE_GET.json`, `SYNTHETIC_FIXTURE_FAILURE.json`, `FINAL_TEST_RESULTS.txt`, `FINAL_PRESERVATION.json`이다. 원본 DB·대형 응답·실험 산출물은 Git에 넣지 않는다.
