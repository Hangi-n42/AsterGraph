# 리테일 질의 입력 예산 수정과 M05 실행 결과

2026-10-19 · 관련 [이슈 668](https://github.com/Hangi-n42/AsterGraph/issues/668)

기존 입력 추정으로 차단됐던 M05의 동일 요청을 실제 제품 경로에서 처음 실행했다. 공급자가 보고한 입력은 새 계산값과 같은 30,208토큰이었다. 검증된 로컬 계약 범위의 입력 예산 수정은 채택했다. M05 답변은 상품 분류에도 확인 불가를 반환하여, 조율자의 원문 독립 대조에서 고정 기준상 부분충족으로 기록했다.

## 입력 계산과 차단 범위

기존 `utf8_bytes/2` 추정 대신, 확인된 로컬 모델의 native prompt와 토크나이저를 대조하는 좁은 계산 경로를 추가했다. 기존 447파일 기준에서 계산 모듈·검사 2개를 추가하고 호출부 3개를 수정했다. 질문·문맥·스키마·검색·모델 전송 코드는 유지했다.

지원 범위는 Ollama 0.40.3의 qwen3.8 renderer, 확인된 로컬 모델 manifest와 내용 해시, API가 제공한 qwen35 BPE 메타데이터, 텍스트 system/user 각 1개와 `think=false`다. 모델명이나 토큰 수를 상수로 고정하지 않는다. 버전·모델 내용·설정·토크나이저 또는 메시지 계약을 확인할 수 없으면 기존 보수적 추정으로 돌아간다. renderer 근거는 설치 버전의 [Ollama 소스](https://github.com/ollama/ollama/blob/eab97e9f92b9a25c2d52d2cc6c1b1c99bd9fae21/model/renderers/qwen35.go)다.

컨텍스트 49,152·출력 예약 8,192·안전 여유 1,000은 유지했다. 스키마 직렬화 토큰은 grammar를 위한 별도 보수적 예약이며 실제 prompt 관측값으로 합산하지 않는다. 따라서 총예산 자체는 정확한 공급자 사용량이라는 뜻이 아니다.

| 요청 | prompt 계산 | 스키마 별도 예약 | 출력과 안전 여유 포함 총예산 | 제품 최종 검사 |
|---|---:|---:|---:|---|
| M05의 보존된 최초 QA 요청 | 30,208 | 154 | 39,554 | 허용 |
| 국소 기여를 복구한 기존 join | 50,247 | 2,199 | 61,638 | 차단 유지 |

저장된 공급자 관측 21건은 모두 prompt 계산 차이 0이었다. 계산 준비의 최초 내용 해시 검증은 파일을 실제로 읽는다. 저장 요청 대조의 최초 준비는 6.820146초, 별도 M05 실제 실행 프로세스의 준비는 7.720404초였으며 모델 생성 시간과 구분했다. 가중치 모델을 초기화하거나 별도 추론 서버를 띄워 계산하지 않았다.

## M05의 실제 실행과 답변 한계

원본 DB의 별도 복사본에서 `business_use.query`와 제품 최종 guard를 거쳐 기존 `ModelClient.generate`를 실행했다. 원본 질문, 12개 주장·12개 검수 의미·25개 출처 view, 전체 messages/schema/reference_map 및 설정이 원래 차단 요청과 같았다. 원본 snapshot·raw 12자료와 기존 실패 기록은 보존했다.

M05의 완료된 검색 결과를 정확히 재생했다. 동일 snapshot에서 검색 입력과 필터 요청을 다시 구성하고 보존된 순위에서 제품 규칙으로 12개 후보를 유도했다. 새 검색·임베딩·선택 필터 호출은 없었다. 자율 검색 개선이나 벡터 재사용 성능을 측정한 실험은 아니다.

실제 QA는 1회, 재시도 0회이며 입력 30,208·출력 190토큰, client의 모델 호출 시간은 204.508489초였다. 예측 prompt와 공급자 관측의 차이는 0이었다. 완료 후 해당 모델을 해제하고 상주 모델 목록이 비었음을 확인했다.

답변은 즉석조리식품, 두부 포함, 제조일로부터 6일이라는 사실을 올바른 후보 3개로 인용했다. 전달된 출처 view 25개를 원본 구간과 대조했고 인용 주소 오류는 0개였다. 실제 로트 만료일이나 임박 재고를 만들어내지 않았다. 그러나 첫 문장은 두부 원재료 상품으로의 분류도 확인 불가로 처리했다. 완제품 분류와 원재료 포함의 차이를 명시적인 결론으로 답하지 않았고, 실제 제조일·로트·재고라는 부족 정보도 구체화하지 못했다. 이는 부분충족이며 허위 사실 생성이나 전체 오답으로 판정한 것은 아니다. `answered`는 제공 ID·응답 형식 검사 상태이며 전체 질문의 의미 충족을 보증하지 않는다. 제조일부터 6일은 답변에 쓸 경우 정확해야 하는 선택적 예시이고 새 필수 기준으로 추가하지 않았다.

기존에는 QA를 전송하지 못했으므로 이번 결과는 첫 응답의 실행 복구다. 전후 의미 정확성 개선 비교가 아니며 의미 능력·자율 검색·자동 교정 개선은 확인하지 못했다.

## 검사와 남은 범위

최종 계산기·호출자 검사 34개가 통과했다. 더 넓은 관련 검사에서는 153개 통과·7개 실패가 나왔다. 이 수치는 겹치는 검사 묶음이므로 합산하지 않는다. 실패 7개만 원래 447코드에서 다시 실행했고 이름·전체 오류 메시지가 모두 같았다.

그 7개는 수동 run의 `units` 누락 2건, synthetic origin의 `requirements` 누락 4건, mock source 재판정 응답이 현재 필수 `inspection_status/findings`를 누락한 1건이다. fixture 계약 불일치가 관측된 것이며 실제 모든 legacy DB의 호환성을 확인했다는 뜻은 아니다. 기대값이나 해당 제품 코드를 이번 작업에서 수정하지 않았다.

다른 모델·버전·도구/이력 메시지의 정확 계산과 새로운 자율 검색은 검증하지 않았다. M02·M03의 이전 의미 실패, 전체 검토 완료, 사람 승인, Scope 교정은 이번 결과로 해소되지 않는다. 미채택 1A·1B·국소 기여 수정은 합치지 않았고 같은 join이나 다른 QA를 재시도하지 않았다. 닫힌 실패 계열 6/6과 누적 잔여 횟수 확인 불가 상태도 초기화하지 않았다. 이슈 668과 전체 목표는 미완료다.

로컬 증거 묶음은 `retail-knowledge-pilot-20261018/model_input_budget_v1/`의 `verified_code_manifest.json`, `product_counter_native0_result.json`, `preflight/receipt.json`, `actual_QA/receipt.json`, `actual_QA/actual_answer_evidence_review.json`, `baseline447_failure_replay_comparison.json`이다. raw·DB·큰 원시 응답은 Git 공유 대상에 포함하지 않는다.
