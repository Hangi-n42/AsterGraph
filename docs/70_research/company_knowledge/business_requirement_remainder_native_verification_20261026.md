## 적용성 연결: 확인된 범위

고정된 10개 의미 × 원래 요청 항목 3개, 총 30개 조합을 34개 원문 블록과 대조했다. 조합별 true 8·false 22, 의미별 집계는 레시피·앞다리 상품·등심 상품 3개 true, 일반 안내 7개 false였다. 수신 오류·누락·중복·meaning challenge는 없었고 저장·GET과 `source_checks` 소비에서 같은 집계를 유지했다.

이는 필수성 전달을 입증한다. 전체 M03 충족을 입증하지 않는다. `batch5:m1`의 일부 이유가 다른 의미 m3의 특성을 가져왔고, background 행도 `requested_fact`를 비우지 않았다. 필수 3개는 전체 조리 절차·브랜드·중량 등을 포함하는 복합 의미다. 해당 하위 내용 전부가 원래 부위·용도 질문에 필수라는 근거는 없다.

## 일반 R: 필드 반환과 상태 모순

초기 R 6회가 승인됐으나, 공통 계약 결함으로 3회 뒤 중단했다. R4~R6 전송은 0회다. 세 모델 응답은 모두 정상 stop이다. 이미 전송된 R3의 원시 응답과 실제 소비 상태까지 보존한 다음, R4 전송 전 이 harness만 SIGINT로 중단했다. 프로세스 종료 코드 130과 모델 응답 실패는 구분한다.

이 모순은 서버가 partial로 바꾼 결과가 아니라 native 원시 응답 자체에 있다. 특히 R3 m3의 reason은 “일부만 표현되어 partial”이라고 쓰면서 status는 represented였다. 원시값을 보정하거나 정상 partial 사례로 세지 않았다.

### 프로그램 소비 경로에서 확인한 결함

1. `business_models.ContributionCheck`는 세 잔여 필드를 필수로 받지만 status와 잔여의 일관성을 검사하지 않는다. 모순 행이 수신 검증을 통과했다.
2. 실제 `business_review._represent`의 국소 receipt도 이 모순에 error를 남기지 않았다.
3. `summarize_local`은 status가 partial인 행에서만 잔여를 옮긴다. 따라서 모순 represented 행은 요약에서도 represented로 남고 `missing_content/missing_evidence`는 옮겨지지 않았다.
4. 저장·GET은 두 층을 그대로 재현했다. `review_scope.batches`의 실제 receipt에는 잔여가 남고, compact representation에는 같은 잔여가 없다. 서버가 검출·보류하지 못한 문제다.

새 필드가 실제 반환·주소 복원되는 연결은 확인했다. 모순 없는 일반 partial → 최종 잔여 확인 → recoverable → 교정 연결은 검증되지 않았다. 종합·교정은 실행하지 않았다.

### 추가 의미 판정 한계

- R1 recipe는 전체 represented였으나 재료의 양은 c3.raw 및 interpretation의 표현 값에 없고 원문 `evidence.quote`에만 있었다. 필요한 ‘돼지고기(등심)’은 후보 raw에 실제 있다. 핵심 질문 사실과 복합 의미 전체 표현은 다르다.
- R3 m2는 수치가 없는 c38.raw의 “부위마다 다르다”와 원문 인용의 수치를 혼동해 전체 represented를 정당화했다. R2에는 실제 수치 후보 4개가 있지만, 이는 R3의 국소 기여 판정을 정당화하지 않는다.
- R1은 이번 묶음 밖의 상품을 “후보로 추출되지 않았다”고, 이미 저장된 c198/c199를 “새로운 제안”이라고 설명했다. 국소 미발견과 전체 저장 누락은 다르다. 원래 객체·교정이 사라진 결과가 아니다.
- 잔여 표는 분석자의 원래 질문·원문·실제 후보 대조다. 필수성 라벨이나 repair 대상을 수동으로 변경하지 않았다.

## 다음 작업과 결정 사항

최소 후속 수정 계획은 represented인데 명시적인 잔여 내용·근거가 있는 행을 해당 의미의 보류/오류로 기록하고, 원시 잔여와 정상 형제 행을 보존하는 것이다. 자동 partial 변환으로 응답을 고치지 않는다. 일반 R와 종합 revision 소비 경계에 같은 일관성 검사를 적용하고, 실제 R2/R3 모순을 회귀 fixture로 고정해 정상 행 보존을 확인해야 한다.

이 수정만으로 복합 의미의 하위 내용 전부가 필수로 소비되는 문제나 모델 의미 정확성이 해결되지는 않는다. 복합 의미의 질문상 필수 부분과 참고 부분 문제는 별도 범위 결정으로 남긴다. 새 계약 수정·모델 재실행은 시작하지 않았다.

검증 보고 범위에서 현재 사용자 결정이 필요한 사항 없음. 후속 계약 수정을 착수하려면 별도 범위를 결정해야 한다. 본 단계는 실제 호출·저장·GET·보존 및 결함 재현으로 검증했으며, 제품 코드 변경이 없어 테스트를 재실행하지 않았다. 호환 패치의 기존 38개 테스트 통과를 이번 의미 검증 성공으로 세지 않는다.
