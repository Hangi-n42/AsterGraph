# 일반 검수 입력의 비손실 참조 — 2026-10-26

## 진행 이유와 범위

일반 검수의 반복 원문을 줄이기 전에 같은 저장 입력의 완전 복원과 정확 토큰 감소를 검증했다. 기반은 `b7daf1457005621da4f9588342a4f722d08c2339`이며 기존 교정 입력 압축 `21eb9b0b`를 포함한다. 별도 `codex/representation-lossless-input` worktree에서 진행했다.

변경은 `requirement_representation` 중 `mode=meaning_batch`인 **국소 검수**에 한정한다. 최초 검수와 `after_repair` 재검수가 같은 요청 생성 경계를 사용한다. 같은 stage의 종합 `requirement_join`, 교정·적용성·QA·원문 검수에는 적용하지 않는다. 기존 출력 계약·주소 검증·선정·완료 판정과 분할 정책·문맥 한도·출력 예약은 유지했다.

기존 간결한 JSON, 짧은 b/c/v ID와 출력 eN은 이미 적용된 기능이므로 새 절감으로 세지 않았다. 기존 `repair_input_references`의 ID/absent 필드 확장은 별도로 비교했지만 이번 변경에는 넣지 않았다. 원문 근거 공유 하나로 충분한 이득이 확인됐고, 추가 필드·ID 해석 범위를 넓히지 않기 위해 제외했다.

## 최소 변경과 안전 경계

`source`, `whole_candidate_judgments`, `claims`, `repair_context` 아래에서 `block_id`와 `quote`를 가진 **근거 dict 전체의 직렬화가 동일한 경우만** 요청 안의 `shared_input_evidence`에 한 번 전달한다. 원래 각 위치에는 전용 `input_evidence_ref` 객체가 남는다. 값의 공유이며 후보·의미·역할·조건의 병합이 아니다.

인용뿐 아니라 문서·버전·파서·절대 구간·`precision`·`context_only`와 추가 필드를 그대로 보존한다. 키·배열 순서, null/누락/unknown/빈 배열, 숫자·불리언·문자열도 바꾸지 않는다. 다른 주소·버전·필드 값의 객체는 합치지 않는다. 원문·reason·후보·필수성·조건·예외·기간·실패 상태를 삭제하거나 재분류하지 않는다.

공유표는 실제 같은 payload 안에 있으며 과거 대화나 외부 저장 참조를 가정하지 않는다. 표는 읽기 전용이고 출력 근거는 기존 blocks의 eN만 선택한다는 설명을 추가했다. 입력·스키마·기존 참조표의 별칭 충돌을 피한다. 원래 marker가 있으면 원형을 유지하며, 기존 공유표를 덮어쓰지 않는다. 복원 시 없는 참조는 거부한다.

참조 후보가 있는 요청만 전후 정확 prompt를 비교한다. 추가 설명을 포함해 실제 토큰이 감소한 경우에만 적용한다. 정확 계수 미검증 또는 이득 없음이면 원래 messages를 그대로 사용한다. 중복이 없으면 추가 계수도 하지 않는다. 근사 바이트 절감을 정확 토큰 이득으로 대신하지 않는다.

## 제품 경로와 자동 묶음 변화

최근 고정 6개는 현재 제품 `json_request`로 원래 요청 전체가 정확히 재구성되는지 확인한 뒤 변경 요청을 비교했다. 이전 after_repair 5개는 저장된 이전 출력 계약을 유지한 채 같은 제품 참조 경계에서 비교했다. 이를 현재 잔여 필드 계약의 새 모델 판단으로 세지 않는다.

## 비용과 트레이드오프

추가 정확 계수는 `packs`와 캐시 조회에도 생긴다. 최근 경로의 계수 호출은 12→18회, 관측 계수 시간은 0.647→0.999초였다. after_repair 경로는 8→12회, 0.487→0.761초였다. 경로 wall은 각각 16.261→13.830초, 14.475→13.741초였지만 단일 순차 관측이며 캐시·처리 크기 영향이 분리되지 않았다. 속도 개선의 인과 근거로 사용하지 않는다.

실제 제품 helper의 복사·참조·직렬화는 요청당 1.21~2.99ms, 확장·전체 메시지 바이트 검증은 1.84~2.50ms였다. 계수 포함 제품 요청 경계의 첫 관측은 6.436초로 첫 블롭·토크나이저 검증을 포함했고 나머지는 0.066~0.094초였다. 최근 6개는 전체 요청 builder, 이전 5개는 저장 요청에 대한 참조 경계 비용이다. 모델 지연이나 반복 성능 평가가 아니다.

변경 messages의 hash는 이전 생성 요청과 다르다. 과거 응답을 변경 입력의 exact-generation 캐시 재사용으로 승인하지 않는다. 기존 캐시의 정확 요청 비교를 완화하지 않았다.
