## 범위와 구현

기준은 `feature/knowledge-review-repair`의 `f369091704c0dee59c393c8aa36929ec1dc561da`다. 기존 Q4 진단의 B1 실패 후보 7개/B2 정상 대조 7개와 8사실·평가기준을 재사용했다. 사람 고정 대상이며 자동 선정 성과가 아니다. 원문 대조 2회 안의 16대조이며 역할 전체 상한은 6회다.

혼합 검수 뒤에 새 단계를 추가하는 대신, 명시적 opt-in 진단 분기가 기존 원문 조사·업무 필수 선정·후보 원문 검수·국소/종합 표현 검수를 업무→원문→최종 업무의 세 호출로 대체한다. 기본 경로와 공개 API 옵션은 유지한다. 신규 모델·DB 종류·범용 프레임워크는 추가하지 않았다.

- 첫 업무 담당은 원래 질문과 실제 저장 필드·조건/예외 상태·관계/전제 구조·출처 ID를 받는다. 원문 evidence/participants 인용·수량 정답·고정 필요성 판정은 받지 않는다.
- 원문 담당은 판정·필수성·이유를 제외한 검사 범위와 원문/부모 문맥, 실제 저장 필드를 받는다. 사람 고정 8범위는 업무 담당의 실제 검사 요청과 구분한다.
- 최종 업무 담당은 전체 원문을 다시 받지 않는다. 실제 저장 필드와 원문 검수 결과·주소 검증 상태를 분리해 필요성/국소 충족을 의미 재판정한다. 원문 결과를 저장 지식으로 합치지 않는다.

ID·출처·버전·문자 주소·중복 검증과 정상 부분의 보존을 재사용했다. 전체 후보 목록이 미확인인 국소 미발견은 복구 대상으로 승격하지 않는다. 근거가 없는 교정과 필수성 미확정을 차단한다. 합성 양성 대조에서는 정상 기여와 실제 잔여가 기존 교정 선정 함수에 전달됨을 확인했으며 실제 교정은 하지 않았다.

진단 결과는 복사 run의 `role_reviews`/`role_review_assessments`와 실제 units에 저장한다. 기존 assessments 및 requirements의 최신 평가·상태·이력은 갱신하지 않는다. 저장 불변은 의미 보존 검증 완료와 구분하며 `preservation_complete=True`로 표시하지 않는다.

관련 **91개 검사 통과**. 복사 DB에서 양 묶음의 6개 합성 콜백을 실제 입력→소비→저장→API GET 경로로 검증했으며 실제 모델 HTTP는 0회다. 합성 응답은 모델 성과가 아니다. 과거 실제 저장 응답 2건의 표현 주소 경계 재생도 새 역할 프로토콜의 실제 응답과 구분했다. 중간 준비 DB/응답은 별도로 보존했다.
