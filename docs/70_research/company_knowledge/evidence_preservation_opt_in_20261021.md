# 검색 근거 보존 옵션의 기술 연결 검증

2026-10-21, 기반 main `55f0bf77f89e32992ac3f3c1afcefe4d70a05c7c`.

## 변경 범위

기본 검색과 `limit` 동작을 유지하고 `evidence_union=ranked_preserved_claims_v2`를 명시적으로 선택할 때만 새 조립을 사용한다. 지원 범위는 snapshot·graph·hipporag2·synthesis이며 명시적 requirement_ids가 없어야 한다. 기존 미채택 `selected_factual_claims_v1` 계약이나 W1 선택기는 통합하지 않았다.

이 옵션에서 limit는 같은 검색의 기존 기본 근거 수다. 기본 근거와 실제 선택 사실을 필수 집합으로 보존하고, 같은 전체 순위에서 whole claim을 처음 등장한 순서로 추가한다. 최종 상한은 기존 token 예산이며 21개를 고정하지 않는다. 필수 집합의 용량·주소 실패는 QA 전 실패로 저장한다. 선택적 추가가 처음 초과하면 마지막 통과 입력·문맥·별칭·원문 순서·의미·연결 상태를 복원하고 뒤의 후보는 시도하지 않는다.

최초 원문 조립은 기존 출력을 유지한다. 이후에는 같은 요청의 전달 순서를 유지하고 새 참조만 추가하며, 같은 블록의 앞쪽 비연속 span도 다룬다. 겹침·연속 구간 합병과 참조 재정렬을 구별하고 precision·절대주소를 보존한다. 상태는 다른 질문/run/version에 공유하지 않는다. claim context 열거와 q 별칭의 기존 규칙은 바꾸지 않았다.

공통 json_request·예산 가드·별칭 복원·Answer 검증·저장/DTO를 재사용한다. counter는 검증된 Ollama 0.40.3과 0.40.6을 함께 지원한다. 이에 따라 0.40.6은 기존 보수 fallback 대신 검증된 계수를 사용할 수 있으며, 그 외 계약은 기존 fallback을 유지한다.

## 검증 결과와 분리

고유 검사 161개를 확인했다. 기존 관련 160개 일괄 검사가 통과했고, 의미 bundle 확장 검사 1개를 추가한 뒤 해당 집중 검사 18개를 다시 통과했다. 중복 실행을 검사 건수에 더하지 않았다. 지원 범위, 필수/선택 초과, 전체 rollback, 잘못된 주소, 같은 블록 인용 순서, 의미·미확정·오류 투영, 비어 있지 않은 사실 선택의 API 연결, 저장/재조회와 다른 질문 비누출을 포함한다.

실제 새 모델·임베딩·선택·QA·추출 호출은 0회다. 명시적 fixture의 CPU 순위 계산, metadata-only 로컬 계수18회와 저장 계수 재사용21회를 별도로 기록했다. 재생 raw에 남은 과거 provider 토큰과 시간은 새 사용량/성능으로 더하지 않는다.

일반 fixture API의 평가 normal13은 기본3개→최종7개이며 기존 포함분 손실은 없다. 13개 전체가 도달했다는 뜻은 아니다. IF/OR 원문은 기본/최종에 있었고 보관 원문은 양쪽에 없어 보관 보존 성공으로 세지 않았다. 저장 W1 재생은 과거 final21과 같아 해당 원문 채널도 동일하다. 의미 행의 추가 claim 연결과 기존 claim의 조건·상태·오류·근거 보존을 구별했다. 초기 후처리의 claim_support 사전 키 역복원 누락과 fixture 준비/미도달 오류도 원기록과 함께 보존했다.

## 보존과 다음 범위

원본55파일·기존 dirty13파일·기존8개 checkout·11개 서버 PID와 원본 DB를 보존했다. 복사 DB의 기존18개 테이블 전행은 동일하며 신규 run6개만 추가했다. DB·원응답·대형 artifact는 Git에 넣지 않는다. 실행 근거는 로컬 artifact `main_evidence_preservation_native0_20261021`에 있다.

이번 변경은 명시적 opt-in의 기술 연결 후보다. 기본 채택, 실제 main 자율 검색, 새 답변 의미 품질·일반화는 검증하지 않았다. 120g 사용량/500g 포장중량 구분 능력도 미확인이다. 기존 최소18/19, closed semantic6/6/no_reset과 global exact/remaining=null을 유지한다.

다음 단계가 필요하면 먼저 동일 검색의 기존/새 최종 근거 도달과 정상 보존·예산을 평가하고, 그 통과 조건과 별도 실행 예산을 확정한다. 관계 선택 누락과 최종 순위 확장의 도달은 따로 판정한다. 새 모델 호출·기본 채택·병합·배포·이슈 종료는 이번 범위에 없다. 현재 사용자 결정이 필요한 사항 없음.
