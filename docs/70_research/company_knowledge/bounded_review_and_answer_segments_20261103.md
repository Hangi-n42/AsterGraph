## 제품 코드에 남긴 독립 수정

명시적 `provided_review_scope_segments_v1`을 선택하면 모델은 답변과 한계 설명을 각각 `{text, claim_refs, quote_refs, review_refs}` 배열로 반환한다. 별도의 본문 문구와 anchor를 생성하지 않는다.

- 프로그램이 `text`를 그대로 이어 본문을 만들고 위치를 계산한다. 굵은 표시·공백·반복 문장도 변경하지 않는다. 같은 문장이 두 번 나오면 배열 내 각 위치를 유지한다.
- 기존 모델 raw는 보존한다. 새 구조의 화면용 표현을 계약대로 만드는 것이며, 실패한 원시 응답의 사후 보정이 아니다.
- 원문 인용 위치, 제공·전역 인용 주장 ID, 원문 참조 ID, 검수 참조와 전달된 전제 검사는 유지한다. 원문 참조와 검수 참조를 같은 문장에 섞으면 거부한다.
- 기존 계약의 “정확하고 유일한 anchor” 검사는 그대로다. 새 계약은 문자열 검색 대신 문장 객체의 위치를 사용하고, 해당 위치의 본문이 원래 `text`와 정확히 같아야 한다.
- 기존 저장·GET·워크벤치 표시 형식으로 연결한다. 사용 버전·검수 지문 변경 차단과 용량 초과 재개도 같은 경로를 사용한다.

기본 인용 계약은 변경하지 않았다. 새 계약은 검수 연결 질문에서 명시적으로 선택할 수 있으며 **실제 모델 QA 검증은 미실행**이다. 기존 `answer_review.correct`의 지원 범위는 확대하지 않았다. 실패한 최종 검수 프롬프트·스키마는 PR 제품 코드에서 제외했다.
