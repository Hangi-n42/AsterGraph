# 확정 불가 근거 연결과 보강 후 필드 상태 — 2026-11-03

보강 후 보조 필드 표시와 실제 상세 조회 오류는 수정했다. 확정 불가 판단을 검토 범위에 연결하는 새 계약은 부분 개선만 확인했으며 기본 동작으로 채택하지 않는다. 전체 과제 완료나 답변 의미 정확도 향상으로 보고하지 않는다.

## 왜 이 범위를 수정했는가

기존 M03 답변은 상품의 부위·용도 차이와 레시피 부위 비교를 보존했지만, ‘상품 지정·적합성을 확정할 수 없다’는 문장을 레시피 재료 목록 하나에 연결했다. 재료 목록은 레시피의 등심 사용을 보여 주며, 전체 자료에 적합성 근거가 없다는 증명이 아니다.

고춧가루·부위 안내 보강 문장은 지정 범위 재검수를 통과했지만, `qualifier_status=unparsed_model_edit_requires_review`였다. 고춧가루의 `period="unresolved"`를 그대로 기간으로 표시하고, 재검수 이력과 조건·예외·기간 필드 검수 상태를 구분하지 못했다. 실제 보강 DB의 상세 조회에서는 추가 항목의 `before=None`에 `.get()`을 호출해 오류도 발생했다.

## 제품 코드의 변경과 적용 범위

- `KnowledgeWorkbench`는 보강 후 보조 필드가 미검수임을 표시한다. 빈 배열을 ‘조건·예외 없음’으로 확정하지 않고, 해당 미검수 상태의 `period="unresolved"`는 ‘미확인’으로 보여 준다. 원래 값은 별도의 원본 펼침에 그대로 남긴다. 실제 기간 문구 ‘가급적 빨리’도 미검수 값임을 함께 표시한다.
- `rechecked_in_scope` 이력은 ‘지정 범위 재검수 통과’로 표시한다. 기존 `unreviewed`, `semantic_status=unknown`, 사용자 사용 승인 상태는 바꾸지 않는다.
- 보강으로 새 항목이 추가됐을 때 변경 전 문장이 없어도 상세 조회가 성공하도록 `None`을 처리한다. 저장 레코드는 수정하지 않는다.
- 새 `provided_review_scope_links_v1`은 **명시적으로 선택하는 실험 계약**이다. 동일 질문·요구·승인 버전·저장 표현에 연결된 기존 최종 검수의 `undetermined` 판단만 참조할 수 있다. 프로그램이 판단 참조 ID를 만들고 모델은 그 ID를 답변 문구에 연결한다. 원문 인용과 검토 범위 참조를 같은 연결에 섞으면 거부한다.
- 검토 범위 연결에는 이전 판단과 이유, 비교 전제의 원문 위치·저장 표현·조건·원문 버전·사용 버전·검수 실행을 저장하고 화면에 구분해 표시한다. 주소 연결이 맞아도 `semantic_support=not_assessed`다. 일반 질문과 기존 검수 연결 질문의 **기본 인용 계약은 변경하지 않는다**. 기존 명시적 원문 참조 정정 도구 `answer_review.correct`는 기존 인용 계약만 지원한다.
