# 사실 소속·인용 위치 수정과 같은 누락의 보강·재검수

**고춧가루 보관 정보 두 건과 부위 안내의 보관 권고 두 건을 문서별 복사 DB에서 보강·재검수까지 완료했다. 두부조림의 정상 정보 세 건은 보강 없이 유지했다.** 원시 응답 수정, 인용 검사 완화, 사용 버전 승인·전환은 하지 않았다. 이는 앞선 실패를 보고 수정한 동일 사례의 결과이며, 미노출 문서에서의 일반 성능이나 전체 제품 완료를 입증한 결과는 아니다.

## 왜 이 변경을 했는가

[수정 전 교차 문서 실험](cross_document_repair_probe_20261102.md)에서는 필요한 값을 찾고도 사실의 소속을 다시 잘못 생성하거나, 맞는 인용 문구에 틀린 숫자 위치를 붙여 후속 작업이 중단됐다. 모델이 다시 만들 필요가 없는 정보를 프로그램이 맡도록 바꿨다. 원문·질문·최초 자동 구축본 197개·평가 대상 누락 네 항목과 정상 다섯 항목은 유지했다. 지식을 삭제해 누락을 만들거나 정답을 생산 입력에 추가하지 않았다.

- **사실 소속:** 모델은 기존 사실 ID와 질문에서의 사용 목적만 선택한다. 원문 의미의 소속은 그 ID에서 프로그램이 조회한다. 고춧가루의 보관·원재료 사실을 상품명 의미 아래에 다시 붙이던 오류 세 건이 새 응답에서는 없어졌고, 필요한 세 사실은 모두 필수로 남았다.
- **인용 위치:** 모델은 허용된 원문 참조와 정확한 구절을 선택한다. 해당 범위 안에서 한 번만 일치할 때만 프로그램이 위치를 확정한다. 반복·범위 밖·다른 버전·원문과 다른 문구는 거부한다. 부위 안내의 새 인용은 `[647,677)`, `[679,703)`에 연결됐다. 과거 잘못된 span 응답을 재배치하지 않았으며, 이전 계약으로 재생하면 여전히 실패한다.
- **입력 중복:** 동일한 원문 주소·구절을 참조 묶음에 한 번 저장해 재사용한다. 원문 사실이나 조건을 합치거나 요약하지 않았다. 기존 소속·대상·속성·버전은 그대로 남는다.

새 계약은 명시적인 실험 run 설정으로 선택한다. 기존 생산 계약의 기본값과 저장 응답 재검증을 보존했다. 이름이나 음식별 정답으로 분기하는 코드는 추가하지 않았다.

보강된 실제 문장은 다음과 같다.

- 참맛고춧가루는 직사광선을 피해 그늘지고 서늘한 곳에 보관해야 한다.
- 참맛고춧가루는 개봉후 지퍼로 밀봉하여 냉장보관하면 고춧가루 특유의 맛을 오랫동안 유지할 수 있다.
- 지방이 많은 부위는 냉장 보관 시 가급적 빨리 소비하는 것이 좋다.
- 지방이 많은 부위는 장기 보관할 때 소분해 냉동하는 것이 좋다.

첫 문장의 보관 지시는 원문의 “보관하십시오”에 대응한다. 두 번째 문장은 조건과 가능한 효과를 함께 보존했다. 부위 안내는 지방이 많은 부위라는 대상과 냉장·장기 조건, 권고의 강도를 유지했다. 새 원문 대조는 이 문장들의 실제 저장 필드를 찾아 누락을 represented로 바꿨고, 업무 최종 검수도 부족에서 범위 내 충분으로 바뀌었다. 저장 GET 성공만을 의미 개선으로 계산하지 않았다.

두 문서 각각의 실제 finalize 함수가 `rechecked_in_scope`를 반환했다. 같은 보강을 다시 요청하면 `no_verified_gap`으로 종료하며 추가 호출·추가 지식은 0이었다. 두 문서의 후보를 하나의 DB나 사용 버전으로 합친 결과는 아니다.

## 중간에 나온 추가 실패도 보존했다

첫 수정 구성은 선정·원문 대조를 세 문서에서 통과했지만, 이후 두 실패로 양성 문서의 보강 완주는 0개였다.

1. 부위 안내의 최종 검수가 “저장에는 없지만 원문에 있으므로 충분하다”고 했다. 제품은 `confirmed_finding_requires_stored_contribution`으로 차단했다. 입력에 저장 누락 정보가 없었던 문제가 아니다. `confirmed`를 원문에서 확인되는 사실로 읽을 수 있던 지침과, 실제 저장 기여를 요구하는 소비 기준이 맞지 않았다. 별도 계약에서 confirmed와 coverage를 저장 지식의 충족으로 명확히 정의했다. 새 응답은 두 누락을 부족으로, 정상 앞다리 정보를 충족으로 구분했다. 소비 검사는 바꾸지 않았다.
2. 고춧가루 보강은 상품명 근거가 빠져 저장되지 않았다. 별도 평가에서는 조건부 맛 보존 효과를 “냉장보관해야 한다”로 강화한 오류도 발견했다. 제품이 자동으로 발견한 것은 참여자 근거 오류이며, 의미 강화 오류는 외부 평가가 발견했다. 완결 문장으로 보강할 때도 조건·가능한 결과·권고 강도를 함께 유지하도록 지침을 명확히 했다. 새 응답은 원래의 조건부 표현을 보존했다.

보완 구성에서도 최초 보강 제안은 참여자 근거가 부족했다. 고춧가루는 제품명, 부위 안내의 두 번째 절은 앞 문장의 주어가 빠졌다. 기존의 별도 근거 선택 단계가 실제 원문 위치를 골랐고, 프로그램은 그 근거만 추가했다. 원래 제안의 문장·Entity·조건·기간은 변경하지 않았다. 최초 실패 응답과 unresolved 보강 기록은 그대로 남는다. 이후 새 후보 자체의 원문 검수와 새 재검수를 모두 실행했다.

후보 자체 검수의 원시 `preservation_checks`는 새 후보에 대해 보존을 선언했지만, 소비 결과는 unknown이었다. 이를 원래 정상 지식 보존의 증거로 세지 않았다. 정상 보존은 원래 197개 항목의 동일성, 기존 그래프 보존, 같은 질문에서 정상 후보를 다시 찾은 결과로 따로 확인했다.

## 긴 본문 39회 반복의 원인과 수정 효과

문서를 39번 검색한 문제가 아니다. 부위 안내의 1,267자 본문 하나가 여러 입력 칸에 복사된 문제다.

원문 의미 여섯 개가 전체 본문을 근거로 사용했고, 세 검사 속성에 연결되면서 18개 사실 기록으로 확장됐다. 각 참조를 다시 인라인 복사한 것이 직접 원인이다.

수정 후 같은 본문 포함은 **39→3회**, 선정 입력은 **41,484→11,184토큰**으로 줄었다. 남은 세 곳은 원본 블록, 전체 블록 인용 `[0,1272)`, 본문 부분 인용 `[4,1271)`이다. 서로 다른 주소를 임의로 합치지 않았다. 참조를 다시 펼쳐 원문·18개 사실·조건·질문 검사가 이전 입력과 동일함을 확인했다.

주소 중복은 줄었지만 전체 본문을 여러 사실의 근거로 잡는 거친 범위와 18개 사실 확장은 남아 있다. 소속 출력 변경과 입력 중복 제거를 함께 적용했으므로 의미 효과를 각 요소에 따로 귀속하지 않는다. 토큰 감소를 메모리·속도·정확도의 일반 개선률로 바꾸어 보고하지 않는다.

## 검증과 비용

- 첫 수정 전후의 관련 단위 검사 238개, 추가 최종 검수·보강 계약을 수정한 뒤 관련 검사 97개가 통과했다. 겹치는 검사이므로 더해 새 총검사 수로 표시하지 않는다. 합성 검사와 새 모델 의미 결과는 별도다.
- 첫 수정 구성 Q4 10회, 보완 구성 Q4 12회로 **새 호출 총 22회**다. 입력 **202,121**, 출력 **9,849토큰**, 호출 시간 합계 **1,718.325초**다. 준비·평가·저장 확인 시간은 제외한다.
- 첫 구성은 앞단 응답 10개, 보완 구성은 선행 성공 응답 17개를 재사용했다. 같은 응답이 후속 run에 나타나도 새 호출로 중복 계산하지 않는다. 실제 생산 코드로 입력·스키마·참조·설정·설치 모델 신원을 대조했고, 실패한 최종 검수·보강 응답은 재사용하지 않았다.
- 설치된 로컬 `qwen3.8:27b-q4_K_M`, temperature 0, think false를 순차 실행했다. 실제 단계별 context는 16,384/24,576/32,768, 출력 예약은 4,096 또는 8,192, 별도 안전 여유는 1,000이었다. 각 실제 HTTP 전송이 동결 요청과 일치한다.
- 제공자 응답은 모두 stop이었다. 제공자·잘림·형식 실패와 위 의미·근거 실패를 구분했다. 같은 구성 재시도·원시 응답 편집·검사 완화·외부 모델 호출은 0이다. 최대 관측 pressure 2, 동시 로드 모델 1, 메모리 기준 중단 0이다. 두 구성의 장부는 remaining=0으로 닫았다.
- 원본 DB와 실패가 포함된 부모 DB 해시, 기존 모든 행·197개 지식·원래 그래프·528개 개념을 보존했다. 새 복사 DB별 추가 지식은 고춧가루 2, 부위 안내 2, 두부조림 0이다. 제품 FastAPI 라우터의 실제 HTTP GET 200과 저장 결과 일치를 각각 확인했다. 자체 임시 서버만 닫았다.
- 이전 교차 문서 16회, 김치찌개 수량 계보 18회, 10월의 닫힌 6회 계보는 별도로 그대로 유지한다. 이번 구성 실패도 새 성공 기록으로 덮지 않았다.

## 반영 범위와 남은 일

검증된 변경은 Draft PR #679의 명시적 선정·검수·보강 경로에 반영한다. 새 계약은 `application_contract`, `source_review_contract`, `final_review_contract`, `repair_statement_contract`로 구분하며 기존 기본값은 유지한다. 이전 원시 응답을 새 계약의 성공으로 재해석하지 않는다.

이번 결과는 기존 두 수량을 넘어 다른 문서의 보관 정보 네 건까지 보강·재검수를 완료한 증거다. 그러나 해당 실패 사례를 보고 수정했으므로 미노출 문서·질문에서의 일반화는 아직 확인하지 못했다. 단계 진행과 의미 평가는 세션이 감독했다. 제품이 모든 의미 오류를 자동 탐지하거나 기본 UI에서 전 과정을 자동 진행한다는 증거가 아니다.

추가 문장은 `unreviewed`, `semantic_status=unknown`, `qualifier_status=unparsed_model_edit_requires_review`다. 요청한 문장·보관 조건·권고를 검증했으며 기간·양태 같은 보조 필드의 정규화 전체를 인증하지 않았다. 고춧가루의 `period='unresolved'`도 원시 상태로 남겨 두었고, 이를 원문에 있는 기간 사실로 인정하지 않았다. 두부조림의 기존 유형·양태 필드 전체도 이번 정상 세 항목과 구분한다.

사용 승인·버전 전환·추가 개념화·새 QA·이번 UI 검증·PR 병합·배포는 하지 않았다. 승인 44개·공개 v1 최초 구축본·통제 시연 v2도 합치지 않았다. 앞선 답변의 판단 한계 문장에 대한 인용 의미 지지 문제는 별도 미완료다.
