## 생성 문맥 계약

`BusinessRunRequest`와 `ConceptRunRequest`의 `concept_source_context`는 `whole` 또는 `verified_table_rows_v1`을 받는다. 생략하면 기존 실행의 정책을 상속하고, 신규 실행은 `whole`이다. 명시적 `whole`은 상속을 덮어쓴다. start/execute/refresh/projection은 같은 메시지 구성 경로를 사용한다.

opt-in 선택은 원문 HTML 해시·완결 parse·전체 독립 section·유일한 직접 표·셀 본문·행/열/병합 범위·대상과 실제 선택 이웃 주장의 원문 주소를 확인한 경우로 제한한다. 기존 `business_html_rows.HEADERS`의 `테마/분야/품목명/분류코드/업종명` 5열 프로필, 한 행 머리글, 병합된 왼쪽 계층과 비병합 오른쪽 두 열이 필요하다. 대상 이름이나 특정 ID는 적용 조건이 아니다. 다른 머리글 역할, 중첩/복수 표, caption, 부분/변경 원문, 미완결 parse, 다중 품목, 불명확한 명시 참조는 기존 문맥을 유지하고 이유를 기록한다.

선택하면 해당 품목의 모든 행, 겹치는 병합 부모, 머리글, section의 제목·표 밖 주석을 유지한다. 실제 이웃 주장 근거도 제외할 수 없다. 다른 section의 기존 원문은 유지한다. 유지/추가/제외 구간·이유, source/parse/span, 참조 map과 의존성은 기록하고 원문 순서로 제공한다. 명시 참조 탐지는 제한된 보조 검사이며 표식이 없다고 의미 의존성이 없다고 판단하지 않는다. DOM 포함 관계는 구조 검증이지 의미상 적용성 승인이나 모든 표로의 일반화가 아니다.

이번 두 표 대상은 각각 111→17블록이다. 기존 입력에 없던 첫 행의 코드26410·유선 통신장비 제조업과 말미 현장 확인 주석을 추가하여 3행을 완성하고 다른 품목 행을 제외했다. 단순 토큰 필터와 구분한다. 근거가 부족했던 다른 사례의 65→15 축소는 채택하지 않았다.
