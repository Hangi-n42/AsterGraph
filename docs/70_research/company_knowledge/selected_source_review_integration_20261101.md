# 자동 선정 결과와 실제 원문·저장 검수 연결

M03의 선정 결과를 실제 저장 지식과 대조하기 위한 명시적 실험 경로다. 기본 사용자 흐름의 자동 활성화, 업무 요구 최종 충족, 교정, 사용 승인, 새 답변의 품질을 완료로 주장하지 않는다.

## 질문과 필요성 판단

질문: “등록된 돼지고기 두 상품은 부위와 용도가 어떻게 다른가요? 김치찌개 레시피에서 지정한 부위와 비교해 확인되는 점과 확정할 수 없는 점을 알려주세요.”

상품의 용도는 상품 비교에 필요하며 이미 선정돼 있었다. 레시피의 등심과 상품의 부위를 비교하는 데 용도를 별도의 필수 전제로 다시 연결해야 한다는 근거는 없다. 따라서 전제 연결 0건 자체를 이 질문의 사실 누락으로 계산하지 않는다. 최종 답변에서 상품 용도 표기의 한계를 설명한다면 이미 확보한 용도 근거도 사용해야 하며, 그 최종 판단은 이번 원문 검수와 별도다.

## 연결 변경과 범위

- 질문의 비교 구조 구성 → 원문 사실의 대상·속성 귀속 → 요청별 필요성 판단의 기존 세 단계와 실제 완료 응답을 보존한다. 재사용 전에 요청·설정·계약의 일치를 확인했다.
- 예전 B1-B/B2-B 각 7개 후보는 수량·조미 조건의 고정 진단용이다. 상품 후보가 없는 이 묶음을 이번 선정 결과에 사용하지 않는다.
- `selected_source_review`는 선정한 세 문서 버전에서 해당 run의 활성 후보 전체 45개를 기존 소유권 선택 함수로 가져온다. 문구나 인용의 유효성을 이유로 후보를 미리 제거하지 않는다. 대상·후보 ID, 문서 버전, 풀 해시를 결과에 남긴다.
- 원문 34블록과 선정한 다섯 사실을 그대로 사용한다. 후보 45개의 개별 주장 전체가 정확하다는 승인이나 전체 그래프의 누락 판정은 아니다.
- 단계 분기 내부의 동명 `assess` import가 원문 검수 함수 호출을 막던 오류를 수정했다.

## 첫 실행에서 확인한 실패와 최소 수정

실제 Q4 첫 호출은 다섯 사실을 represented로 반환했다. 하지만 두 상품의 부위 행에서 후보를 각각 11개·10개 나열하고 저장 인용은 두 개씩만 반환했다. 기존 소비 검사가 이 두 행을 unknown으로 남겼다. 후속 사용 가능 결과는 3건이며, 이 실행은 미채택으로 보존했다.

수정한 B 계약은 `expression_quotes`만 정상 기여의 입력으로 받는다. 각 인용의 후보 번호에서 `claim_ids`를 생성하므로 같은 목록을 모델에게 두 번 요구하지 않는다. 빈 인용, 중복 인용, 잘못된 필드·문구·대상·버전은 계속 차단한다. 이전 원시 응답의 후보 목록을 삭제하거나 검사 기준을 완화한 것이 아니다. 넓은 A 출력은 별도의 기존 진단이다.

## 실제 결과

수정 계약의 새 Q4 호출은 다섯 사실 모두 실제 저장 위치와 함께 반환했고, 소비 검사도 다섯 건 모두 represented로 유지했다. 상품의 부위 설명도 이번에는 해당 부위로 한정됐다. 첫 실행의 3 represented / 2 unknown에서 5 represented / 0 unknown으로 바뀌었다. 서로 다른 계약의 실제 호출은 각각 1회이며, 같은 계약의 재시도는 없다.

수정 호출은 입력 33,324토큰, 출력 902토큰, 약 291.65초였다. 입력 추정은 별도 스키마 예약 3,191 + 출력 4,096 + 안전 여유 1,000을 포함해 41,611이며 context 49,152 이내였다. 기존 로컬 Q4, temperature 0, think false를 사용했고 메모리 취소·잘림은 없었다. 이전 호출은 입력 33,280 / 출력 1,318 / 약 303.43초다. 이 한 사례로 일반적인 효율·정확도 수치를 만들지 않는다.

수정 계약의 관련 검사 126건, 최신 main 기반 관련 검사 241건이 통과했다. 선정 세 단계는 정확히 일치하는 기존 요청과 완료 응답을 재사용했으며 새 선정 호출로 계산하지 않는다. 실제 누락이 없는 다섯 사실의 검수이므로 누락 발견·교정 성능을 측정한 결과가 아니다.

main 기반 코드에서도 모델에 전달할 요청과 실제 원시 응답의 소비 결과가 일치했다. 이어 복사 DB의 실제 loopback HTTP GET 200과 저장 run 전체 일치를 확인했다. 기존 73개 run과 비run 테이블 17개, 원문·지식·교정·검토 상태를 보존했고 사용 가능성 판정도 바뀌지 않았다. 임시 서버는 새로 예약한 포트에서 실행 후 종료했다. 이 저장·조회 검증을 의미 정확성 개선으로 추가 계산하지 않는다.

## 포함·제외·의존성

이 변경은 이전 미커밋 선정 실험의 `question_inspection`, `required_unit_selection`, 원문 검수와 기존 `business_role_review`의 저장 필드·주소 소비 기능에 의존한다. 이를 최신 main 기반에 필요한 파일 단위로 가져왔다. 원래 작업 브랜치의 별도 서비스 메모리 커밋은 포함하지 않는다.

`request_reference_review`의 명시적 실험 계약이 있을 때 단계별 경로를 사용한다. 일반 신규 run에 이 실험을 자동 적용하지 않는다. 구 역할 분리 모듈 전체가 새로운 선정·두 검수 목표를 완성했다고 해석하지 않는다. 원문 대조의 `represented`는 해당 대상·속성의 저장 표현 확인이며, 사용 승인이나 후보 전체 정확성 판정이 아니다.

업무 요구 최종 검수, 실제 누락 발견 후 교정·재검수, 다른 질문·문서의 일반화, UI의 기본 흐름 연결은 별도 검증이 남는다. 새 사용 버전 승인·전환, 배포, 외부 모델 호출은 포함하지 않는다.
