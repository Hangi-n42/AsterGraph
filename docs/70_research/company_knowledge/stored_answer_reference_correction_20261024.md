# 저장 답변의 명시적 인용 정정

기존 `answer_links` 계약은 원문 전용 참조와 부분 연결을 이미 허용한다.
저장된 원시 응답에 잘못 선언된 주장·인용을 ID 복원 오류로 취급하지 않고,
명시 정정의 주체·이유·변경 전후를 남기는 로컬 서비스 경계를 추가했다.

`app/knowledge/answer_review.py`의 `correct()`는 부모 fingerprint와 정정할
기존 참조 목록을 받아 별도 child run을 저장한다. 새 HTTP 쓰기 API나 생성
계약은 없으며, 일반 사용자가 화면에서 편집하는 기능을 제공하지 않는다.

- 원본문·choice·한계 문장·원문 인용·원래 생성 units는 고정한다.
- 원래 답변에 없는 주장이나 quote를 추가하지 않는다. 기존 source-only
  참조와 literal anchor 범위 조정·명시 연결 해제를 재사용한다.
- 기존 주소·anchor 검사, 원문 제한·요구 버전 검사와 runs 저장을 재사용한다.
  `BEGIN IMMEDIATE` 안에서 부모 fingerprint·중복 요청·저장을 검사한다.
- 원시 응답과 사용 버전은 부모에 보존하고, 새 기록의 정정 출처와 과거 생성
  비용을 분리한다. 새 모델 횟수·모델 시간은 0, 정정 경과 시간은 별도 실측한다.
- `needs_review`에서는 새 정정 상세도 공개하지 않는다. 원본 복귀와 조회는
  기존 워크벤치 경로를 사용한다.

현재 실자료 적용의 정정 주체는 **사용자 지시에 따른 Codex 명시 정정**이다.
사용자가 각 내용의 의미를 직접 승인했거나 독립적인 사람이 검수했다는
기록이 아니다. `semantic_support=not_assessed`와 기존 승인·보류 상태를 유지한다.

## 검증과 한계

백엔드 87개, 프런트엔드 26개, TypeScript·대상 ESLint 검사가 통과했다.
실제 저장 답변의 안전 복사본에서 참조만 정정해 기존 저장/GET 및 전체 앱의
원본·정정본 전환을 확인했다. 원본문·한계·핵심 주장과 정확한 원문 인용은
보존했다. 원본 DB·실패 원시 응답·이전 사용 버전은 수정하지 않았다.

이번 작업은 새 답변 생성·자동 오류 검출·모델 자기 교정의 성과가 아니다.
남아 있는 본문 추론을 원문 직접 지지로 승격하지 않으며, 모든 답변의 의미
정확성이나 운영 배포의 완료를 보증하지 않는다. 기존 마트 실증의 구축·승인·
검색·저장 흐름을 재실행하지 않고, 명시 정정과 조회 시연만 추가했다.
