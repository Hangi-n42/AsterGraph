## 최소 변경안

**P1:** 기존 원 질문에 명시된 연속 번호 요청만 연속 원문 문자열로 읽는다. 질문은 재작성하지 않는다. B/C의 기존 전체질문 순위를 보존하고, 같은 고정 원문 색인의 요청별 BM25 순위가 공통 선택 경계에 들어가도록 한다. 요청별 상위 근거를 교대로 선택하되 기존 원문 범위 중복 제외를 재사용하고 최종12묶음·16384예산을 유지한다. 추가 LLM query 분해·새 source 임베딩·정답 근거 목록·자금명 사후 규칙·별도 검수 층은 넣지 않는다. 번호 요청이 없으면 기존 선택 그대로다. 변경 위치는 `graph_retrieval`의 공통 선택 및 `business_use.query`의 source-reader 연결이며, B/C에 같은 조건을 적용한다.

첫 검증은 저장된 B/C 전체 순위와 같은 원문 색인으로 모델 없이 기존 선택의 정확 재생 및 새 문맥을 비교한다. 자율적으로 두 누락 의미가 도달하지 않거나 기존 정상 근거가 사라지면 해당 구성은 QA 없이 기각한다. 도달 후에만 같은 ACT501070 질문의 기존 QA 호출로 이어간다. 검색 도달과 답변의 대상 조건·자금 용도·공백·금리/횟수 예외 오적용을 별도로 기록한다.

**P2:** 선택된 원문 문자열·범위·질문·연결 ID를 고정한 채, 제목·표·주석을 저장 parser의 문서 순서와 DOM 부모 위치로 읽을 수 있게 기존 source-reader QA 입력을 배치한다. 기존 q/b 원문 및 `supports_context_ids`를 보존하고, 구조상 같은 부모에 놓인 원문들을 함께 표시한다. 서버는 `이 주석은 투자자금 제외의 정답이다` 같은 의미 결론을 작성하지 않는다. 자료에 없는 semantic scope·원하는 정정문·평가 관계를 넣지 않는다. 메타데이터를 추가했다는 이유로 품질 개선을 선언하지 않고 실제 답변으로 판단한다.

변경은 reader 전용 source-context 조립과 synthesis 호출의 입력에 한정한다. 추출용 `autoschema.source_packet` 전체를 바꿔 과거 추출·검수 경로에 영향을 주지 않는다. source-reader 선택 집합과 문맥 텍스트의 손실 없는 보존, 다른 source/parse/표·목록의 혼입 차단을 작은 검사로 확인한다. 기존 item-answer/의미 범위 구조화/새 중간 명제 생성은 재사용하지 않는다.
