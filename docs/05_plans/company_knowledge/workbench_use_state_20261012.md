# 회사 지식의 사용 상태·실제 변경 기록 연결

2026-10-12 · 기준 `d10437bf` · 후속 [#663](https://github.com/Hangi-n42/AsterGraph/issues/663)

## 목적과 구현

승인 선택 이력을 현재 일반 활성 버전으로 취급하지 않고, 선택한 저장 결과에서 지금 확인할 수 있는 제한과 당시 사용 버전을 연결했다. 기존 #661/#662의 탐색·편집·그래프 표현은 유지했다. 새 상태 프레임워크·DB·모델 호출은 추가하지 않았다.

- `GET /workbench/usage?kind=run|source_graph&scope_id=...`는 현재 원장의 일반 활성 ID·사용 상태 이력 버전·조회 시각, 원문 버전·파일명·자료 기준일, 출처 지식의 `explicit_query_only`, 저장/현재 요구의 revision·상태, 기존 변경 제외 기록 및 현재 후보 자격 검사 결과를 읽는다.
- `business_use.restricted_sources`, `change_view`, `business_changes.snapshot_invalidations`를 재사용했다. 원문 제한, 요구 revision 불일치, 현재 `needs_review`, 해당 snapshot의 원문 변경 제한을 각각 표시한다. 새 사용가능 bool이나 새 승인 판단은 만들지 않았다. 실제 query의 요구 선택·답변 방식·필수 근거·실행 중 여부 등 검사는 기존 활용 서비스가 담당한다.
- 현황·범위 선택·검토 상세에서 같은 읽기 정보를 확인하고, 추출 실행에서 그 실행의 출처 지식 선택 버전으로 이동한다. 저장 QA는 당시 추출/지식 버전·원문 파일과 현재 읽기 상태를 구분한다. 미승인 원문 QA의 임시 `run:...`는 승인된 snapshot으로 표시하지 않는다.
- 범위 전환은 선택 상세를 초기화한다. 중단된 조회의 늦은 응답을 적용하지 않으며, 새 범위에 과거 사용 상태가 보이지 않게 범위 ID를 대조한다. 필수 조회 기록이 없으면 명시적인 오류를 표시한다.
- source 제목과 version 파일명을 구분한다. 기존 자료군 제목을 보존하면서 범위 선택·후속 링크·당시 QA·실제 인용과 선택 근거에 정확한 파일명/기록 날짜를 표시한다.

새 검증 화면은 `http://127.0.0.1:3014/knowledge`, API는 8014다. 분리 frontend와 새 서울 복사 DB를 사용했다. 기존 3012/3013 및 8012/8013 프로세스는 재시작하지 않았다. 검증 서버는 임시 사용자 launchd job이며 부팅/로그인 자동 실행으로 설치하지 않았다.

## 완료 범위와 한계

완료 범위는 사용·검토 상태와 원문/실행/선택 버전의 읽기 연결, 저장된 서울 변경/비영향 및 QA의 실제 화면 추적이다. 현재 query 정책을 대체하지 않으며 사람 승인·자동 의미 판단의 정확성·전체 업무 요구 충족을 인증하지 않는다. 순번 13 전체 요구는 partial이다. 제공된 파일의 변경 기록은 실제 운행 변경 실행이나 보행·시간 영향 계산 결과가 아니다.

새 모델·임베딩·추출·변경 평가·QA 생성·촬영·PR 병합·배포는 이번 작업에서 수행하지 않았다. 최종 버전·보존·원격 확인은 같은 artifact의 최종 receipt로 확인한다. 기존 원본 및 실험 DB는 커밋하지 않는다. 다음 작업은 이 조회 정보로 실제 활용 요청의 조건을 점검하는 것이며, 의미 판단/전체 종단의 미완료 #620/#506/#613을 이 UI 작업으로 종료하지 않는다. 현재 사용자 결정이 필요한 사항 없음.
