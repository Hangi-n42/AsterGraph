## 진행 이유와 보존 경계

저장된 실제 지식을 현황→탐색→원문·조건→검토·부분 수정→변경·답변 근거 순서로 확인하도록 기존 기능을 연결했다. 원문, 자동 추출, 검토된 출처 지식, 개념 후보, 승인 온톨로지를 구분하며 여러 실험 실행을 회사 지식 총량으로 더하지 않는다.

원격 main `bb046c2686d04219afafab83caeb61ec5889421a`에서 만든 관리 worktree `knowledge-workbench-ui`, 브랜치 `codex/knowledge-workbench-ui`를 사용했다. 비교 브랜치 `be543a89`의 미병합 구현을 가져오지 않았다. #660 전체 비교와 기존 의미 품질 연구는 재개하지 않았다. PR 생성·병합·배포는 수행하지 않는다.

기존 PID 56276(8001), 56281(3000), 원본 DB와 실험 기록은 유지했다. SQLite 읽기 전용 backup으로 만든 복사 DB만 전용 API 8012/8013과 화면 3012/3013에서 사용한다. 최종 확인 시 API PID는 61727/61729이며 최신 `app/knowledge/workbench.py`를 로드했다. 원본 두 DB의 SHA-256은 작업 전후 동일하다. DB, 원시 모델 응답, 원문, cache와 브라우저 캡처는 Git에 넣지 않는다.

회색 배경·흰 패널과 본문 16px/보조 14px을 적용했다. 내부 ID와 상세 위치 JSON은 진단/접기 영역에서 확인한다. 모바일은 목록/상세를 전환하고 접힌 전역 메뉴는 키보드 초점에서 제외한다.

주 탐색 범위는 `run`과 `source_graph` 두 종류다. 기존 `snapshot`, `ontology`는 검토/변경의 별도 도구에서 자기 범위를 선택한다. 선택 범위를 바꾸면 이전 상세·검색 결과를 비우고 취소된 요청의 늦은 응답을 무시한다. `source_graph`는 승인 선택 이력이며 현재 활용 가능 여부는 미확인으로 표시한다.

대상·관계는 저장 ID, 자료·버전은 각각 고유 ID 기준이다. 원문 block, claim, node/edge, 개념화 기록은 별도 단위다. 그래프 자체가 미기록이면 대상·관계 수는 0 대신 미확인이다. 자료 화면은 해당 버전의 **현재 파싱 결과**, 현황과 근거 상세는 **선택 실행이 보관한 자료**를 읽는다. D01에서는 각각 3,721구간과 3,364구간이며 이를 화면에 구분했다.

그래프는 Cytoscape.js 3.33.1(MIT)을 고정해서 사용한다. 기존 frontend에는 해당 탐색 라이브러리가 없었고, 저장된 방향·평행 관계 ID, 선택, 이동·확대를 구현하는 데 사용했다. 지원 API의 근거는 [공식 문서](https://js.cytoscape.org/)다. 4대상 이하는 원형, 5–12대상은 읽기 쉬운 격자, 그 이상은 COSE 배치다. 초기/확장 단계의 대상 한도는 8/20/40개, 관계 한도는 80개다. 캔버스 이름만 26자로 줄이며 전체 이름·원문·조건은 상세와 동등한 키보드 목록에 유지한다. 같은 요소를 선택할 때 배치를 다시 만들지 않아 이동·확대 상태를 유지한다.
